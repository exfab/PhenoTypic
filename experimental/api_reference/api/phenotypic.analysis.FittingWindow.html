phenotypic.analysis.FittingWindow#

class phenotypic.analysis.FittingWindow(*, on: ~typing.Annotated[str, _ColumnRefMarker('measurements')], groupby: ~typing.Annotated[list[str], _ColumnRefMarker('measurements')], agg_func: ~typing.Callable | str | list | dict | None = 'mean', n_jobs: int = 1, warn_threshold: float = 0.1, fail_threshold: float = 0.3, unmatched_groups: list = <factory>, replicate_by: ~typing.Annotated[list[str], _ColumnRefMarker('measurements')], time_col: ~typing.Annotated[str, _ColumnRefMarker('measurements')], min_replicates: int = 3, smooth: int = 9, abrupt_k: float = 10.0, persist: int = 2, rough_roll: int = 7, rough_k: float = 2.5, rough_lag: int = 3, rough_span: int = 12, near_min_tolerance: float = 0.1, min_bar_over_noise: float = 3.0, edge_frames: int = 3, min_series_frames: int = 11)[source]#

Bases: QualityCheck, PlotQc

Propose the frames over which a condition’s replicates agree well enough to fit.

For each groupby combination — one condition — the check builds the per-frame mean replicate coefficient of variation of on, then asks Rule D where that curve is flat and low: the span a growth model can be fitted over without the fit being driven by replicate disagreement. A window is the run of frames where replicates agree, not “where it is growing”. A condition it can answer for is graded by the mean CV inside that span; a condition it cannot is failed, and QC_Window_Outcome says why.

The bar is pooled over the whole run, and that is deliberate. Rule D judges every condition against one absolute abrupt-change threshold, computed from every condition’s curvature at once, because a per-condition threshold is exactly the unequal treatment the rule exists to remove. Three consequences a reader should know:

  • QC_Window_Bar is a run-level constant — the same value on every row of every condition.

  • Adding or removing a condition can move another condition’s window. The verdict is about a condition within this run, not an intrinsic property of it.

  • A condition analyzed alone is never too noisy, at the defaults. With one series in the pool, the bar is that series’ quiet level plus abrupt_k of its own noise units, and abrupt_k (10) exceeds min_bar_over_noise (3). So too_noisy means “too noisy next to the other conditions in this run”. A condition alone can still go without a window for the other reasons (too few frames, or its best agreement in its last frames), but never for noise. Setting abrupt_k below min_bar_over_noise removes that guarantee.

QualityCheck.analyze hands _compute one group, so the bar cannot be computed there; analyze() is overridden to compute every series, the pooled bar and every Rule D result once, before delegating upward.

What a window is good for. Fitting a growth model only inside the window gives a trustworthy rate v, because the frames where replicates disagree are left out. It does not give a trustworthy lag or starting size: a window usually opens after the lag, so a windowed fit has no frames that constrain lambda or s0. Take lag and starting size from a fit over all frames, and the rate from the windowed fit.

The time axis is a frame index, not elapsed hours. Images of different plates never share an hour value, so hours cannot line plates up across a condition; AddFrameIndex numbers each plate’s images in capture order, 1-based. Rule D compares frames with each other and never with an absolute number, so shifting the axis by one shifts every reported window by exactly one and changes no outcome. A window is therefore a span of frame indices: to fit on hours, filter the table on the frame index first, then fit with the hours column as the time axis (see the example). Rule D needs at least 14 counted frames at the default settings.

The metric. Mean measured CV over the proposed window when there is one, +inf when there is not — so the base class’s metric >= fail_threshold fails every windowless condition with no override of its status logic. Windowless conditions therefore tie on +inf and are not ordered among themselves; QC_Window_BestCV (the series minimum) is carried so a reader can still see how close each came. Using that minimum as the metric would pass a condition Rule D rejected as too noisy, on one good frame.

Diagnostic only. supports_object_curation is False: the verdict is about a condition, so QC_Window_Flag never offers colonies for removal, and to_table() collapses to one row per condition rather than writing one identical row per colony into qc.duckdb.

Examples:

A labelled synthetic series: four conditions of three replicate plates, thirty images six hours apart (see make_synthetic_window_series()). Number each plate’s images, then judge every condition in one run:

>>> from phenotypic.analysis import LinearLagModel
>>> from phenotypic.analysis.qc import FittingWindow
>>> from phenotypic.data import make_synthetic_window_series
>>> from phenotypic.post import AddFrameIndex
>>> from phenotypic.schema import CULTURE, SAMPLE, SIZE
>>> condition, replicate = "Metadata_Condition", str(SAMPLE.BIO_REPLICATE)
>>> frame, hours = str(CULTURE.FRAME_INDEX), str(CULTURE.TIME)
>>> radius = str(SIZE.ROBUST_MEAN_RADIUS)
>>> table = AddFrameIndex(plate_by=["PlateID"]).apply(
...     make_synthetic_window_series()
... )
>>> window = FittingWindow(
...     on=radius, groupby=[condition], replicate_by=[replicate], time_col=frame
... )
>>> _ = window.analyze(table)
>>> verdict = window.to_table().set_index(condition)
>>> for name, row in verdict.iterrows():
...     print(name, row["QC_Window_Outcome"],
...           row["QC_Window_Start"], row["QC_Window_End"])
Condition A found 9 26
Condition B found 19 26
Condition C found 9 17
Condition D too_noisy <NA> <NA>

A and B grow identically; B’s replicates take longer to agree, so its window opens later. D gets no window in this run, and says why:

>>> verdict.loc["Condition D", "QC_Window_Reason"]
"bar is 1.1x this curve's own noise (<3): not assessable"

The handoff to a growth fit is a pandas filter on the frame index, then a fit on hours. The windowed fit gives the rate (the series was built with 0.25 px/h):

>>> a = table[table[condition] == "Condition A"]
>>> start = verdict.loc["Condition A", "QC_Window_Start"]
>>> end = verdict.loc["Condition A", "QC_Window_End"]
>>> in_window = a[a[frame].between(start, end)]
>>> fit = LinearLagModel(on=radius, groupby=[replicate], time_label=hours)
>>> windowed = fit.analyze(in_window)
>>> windowed["LinearLagModel_RobustMeanRadius_v"].round(2).tolist()
[0.25, 0.25, 0.25]

Lag and starting size come from a fit over all frames (the series was built with a 30 h lag and an 8 px start):

>>> full = fit.analyze(a)
>>> full["LinearLagModel_RobustMeanRadius_lambda"].round().tolist()
[30.0, 30.0, 30.0]
>>> full["LinearLagModel_RobustMeanRadius_s0"].round().tolist()
[8.0, 8.0, 8.0]

The windowed fit’s own lag and starting size are not those. Its window opens after the lag, so no frame in it constrains either, and the values it reports are not even reproducible: the optimizer lands on different ones on different machines. Here the lag comes out 6 to 15 h too long and the start 1.5 to 4 px too large, on every replicate:

>>> lag = "LinearLagModel_RobustMeanRadius_lambda"
>>> s0 = "LinearLagModel_RobustMeanRadius_s0"
>>> lag_error = windowed[lag] - full[lag]
>>> start_error = windowed[s0] - full[s0]
>>> bool(lag_error.between(4, 20).all()), bool(start_error.between(1, 5).all())

analyze(data: pandas.DataFrame) → pandas.DataFrame[source]#

Build every condition’s series, pool the bar once, then delegate upward.

The order is forced by the algorithm, not by taste. Rule D tests every condition against one bar pooled over all of them, and QualityCheck.analyze() hands _compute a single group — so the bar has to exist before the first group is computed. This method makes three passes:

  1. per condition, the mean-CV series;

  2. once, abrupt_bar() over every series;

  3. per condition, rule_d() against that bar.

The results are stashed on a private attribute and _compute only looks its own condition up. A per-condition bar would type-check, run, and silently reclassify conditions.

classmethod output_unit(member: MeasurementInfo, on: str | None = None) → ResolvedUnit#

Return the unit of the column analyze() writes for member.

The one default every table producer shares, next to output_header(); no analyzer overrides it. A static unit (LINEAR_LAG_MODEL.lam is time) resolves to itself and ignores on. An input-dependent unit (a fitted rate, a model metric, a QC statistic, an edge-corrected value) resolves against the unit of the column it was computed on, so a rate fitted on a radius converts with px_per_mm ** 1 and one fitted on an area with px_per_mm ** 2.

Unlike output_header(), which ignores on for most producers, this needs on for every input-dependent member. That includes the quality checks’ Median, MAD, SE and fence columns (QUALITY_MAD, QUALITY_ZMAX, QUALITY_SE, QUALITY_TUKEY), whose headers never embed the analyzed column: pass the check’s own on (check.on), or the call raises.

summary() → pandas.DataFrame#

Return a one-row-per-group summary of the most recent analyze.

The aggregate columns are prefixed with ``qc_`` so they can never collide with a groupby column on reset_index — a plate-layout column literally named status or num_rows would otherwise raise. The summary therefore always carries the group key columns plus the four prefixed aggregates.

Returns:

DataFrame with columns [*self.groupby, "qc_n_members", "qc_n_flagged", "qc_worst_metric", "qc_status"]. qc_worst_metric is the extreme metric value in the bad direction across the group: group[metric_col].max() when _HIGHER_IS_BAD is True, else group[metric_col].min(). qc_status is the worst status across the group: "fail" wins over "warn" which wins over "pass".

Return type:

pandas.DataFrame
