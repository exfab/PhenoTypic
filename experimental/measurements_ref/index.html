Measurements#

PhenoTypic writes its results as tables. This reference documents every column that appears in them, grouped by the operation that writes it: one page per measurement operation and per analyzer, listed in the sidebar by stage. Each column carries a Type badge that says how far a single value can be trusted; the Tier System page explains the badges.

Reading a measurements table#

Each row of deliverables/measurements.csv describes one detected colony. Its columns come in four blocks, always in this order:

  1. Your experimental metadata, from the --metadata file: strain, condition, replicate and the like (Metadata_Strain). See Metadata.

  2. Measurements, one block per measurement operation in pipeline order. Every column name starts with its metric family: Size_Area is in the Size family and is written by MeasureSize.

  3. Image bookkeeping: the image each colony came from (Metadata_ImageName, Metadata_BitDepth).

  4. Where the colony is: Object_Label, its bounding box (Bbox_*) and, on gridded plates, its well (Grid_*). See Shared columns.

Where tables are written#

A CLI run writes these files under its output directory:

File

One row per

Holds

deliverables/measurements.csv (and .parquet)

detected colony

detected colony

deliverables/measurements_by_category/<Category>.csv

deliverables/qc/qc.duckdb

one table per quality check

each check’s columns; see Quality control in the sidebar

deliverables/<Model>.csv (and .parquet)

fitted group

the pipeline’s growth-model parameters and fit metrics

deliverables/qc/curation_labels.parquet

curated colony

the category you assigned in the results viewer

Analyzers you run yourself return the same columns from analyze().

Reading an operation page#

Every operation page has the same parts:

  1. A one-line summary of what the operation measures, and a link to its parameters.

  2. The table’s facts: what one row describes, where the table is written, and how many columns the operation adds.

  3. One column table per schema, listing each column exactly as it is written. Where a header embeds the analyzed column, the page shows a placeholder (<metric>) and an example.
