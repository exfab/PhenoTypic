# PhenoTypic GUI v1 — feature & test ledger

This file is the source of truth for every user-facing affordance the unified
GUI ships in v1. Each row maps to either an automated test or a manual smoke
step. The pre-commit hook + CI gate verify ``Test ref`` existence for any row
that reaches ``✅ shipping`` status, and the merge gate rejects any rows still
in ``🚧 in progress``.

## Status legend

| Status         | Meaning                                                  |
|----------------|----------------------------------------------------------|
| 🔭 planned     | Specced; not yet implemented.                            |
| 🚧 in progress | Partially built; do not ship — CI rejects at merge time. |
| ✅ shipping     | Implemented + tested + documented.                       |
| 🧪 internal    | Retained internal/legacy coverage; not user-facing.      |

``Test layer`` values: ``unit``, ``integration``, ``e2e``, ``manual``.
``Test ref`` values: ``path/to/test::test_name`` for automated, or
``n/a (manual)`` for manual-only smoke steps. The validator skips ref
resolution for non-``✅`` rows.

See ``GUI_SPEC_V1.md`` for the canonical design.

## Browse tab (source image viewer)

A new top-level `Browse` tab (mounted at `/browse/`) deep-zooms the raw input
images under the selected source root. Two cascading dropdowns (dataset folder →
image) feed a reusable OpenSeadragon viewport with progressive previews,
keyboard navigation, a bounded filmstrip, and a metadata panel. Revisioned
prepared assets persist within a quota. Works offline over an SSH tunnel
(vendored OSD, no CDN).

## Builder linear port map

The default builder surface is a fixed linear port map backed by the same
internal DAG state and `ImagePipeline` JSON/runtime APIs. Nodes are not
user-movable; image-flow and parameter ports are real Dash/HTML buttons. The
selected node for inspection stays separate from the green add/fill target.
Non-linear development DAG states remain loadable but render a defensive
unsupported-state panel instead of silently flattening.

segmented toggle. **Configure** composes one Plotly card per configured
`QualityCheck` analyzer; each card subscribes to `STORE_REMOVED_KEYS`

only rewritten by an explicit, backed-up compatibility migration. **Review** is the master–detail
curation walkthrough (worklist → detail gallery → per-group recompute);
its affordances are listed in the next section.

## QC Review sub-view

The QC tab's **Review** mode (`_qc_tab/review/`) is a master–detail
walkthrough of the worst-agreeing groups for a selected QC module. It
reads the CLI-written `deliverables/qc/qc.duckdb` (the `qc_modules` catalog + one
self-describing table per module) through the `review/_db.py` read API,
reuses the colony-view tile gallery (`gui/_shared/tiles.build_tile_grid`)
for per-colony curation against the shared `STORE_REMOVED_KEYS`, and

## Error analysis tab

The Results Viewer's 5th tab (`tab-error`) runs `ErrorCutoffFinder`
for the focused error category against a good baseline (all-unlabeled
or verified-only) and surfaces a ranked cutoff table, a good-vs-error
distribution figure with a draggable cutoff line, a live
recall/specificity readout, and a copy-able filter spec. Recompute is
debounced on the curation store + gated to the active tab so the finder
never runs while the user is curating elsewhere. Activation, category
switching, and baseline changes are compute-only previews. Only the explicit
**Publish all categories** action transactionally publishes one complete
generation plus its manifest and receipt; it records empty categories and
never exposes a partial category set. The heavier `error_analysis.html` is
written only by the explicit Save button (and CLI finalize, Phase 5) via the
shared `analysis._helper._error_report` renderer.
