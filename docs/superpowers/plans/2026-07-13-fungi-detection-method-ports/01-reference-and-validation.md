# Reference and numerical-validation protocol

## 1. Reference corpus before claims

Each method receives a directory under:

```text
docs/superpowers/specs/2026-07-13-fungi-detection-method-ports/refs/<method>/
```

Required contents:

```text
PROVENANCE.json       # URL, immutable revision/DOI, retrieval date, SHA-256, license
LICENSE*              # exact license text for code artifacts
paper.*               # primary paper or an archived stable copy
source/               # complete relevant implementation, not copied snippets
RUN.md                 # exact build/run command, versions, compiler, platform
reconciliation.md      # production line or block -> refs/file:line -> decision
```

Where references disagree, the contract records the chosen authority and one drift row for each
fork. Runnability does not make a fork authoritative. Papers and code older than five years are
flagged as older sources in this fast-moving software context, but age alone does not invalidate
an algorithm definition.

## 2. Golden fixtures

Fixtures live under `tests/fixtures/<surface>/<method>/`, normally with
`surface="reconnect"`. Analysis-only A11 path 1 uses `surface="analysis"`. They are immutable after
review unless the reference revision or a recorded drift changes. Each fixture stores:

- every input, including masks, orientation, scale, connectivity, and polarity;
- every public output, including diagnostic tensors, scores, valid masks, and track metadata;
- input/output dtype, shape, axis convention, and boundary mode;
- reference revision and fixture-generator SHA-256;
- source runtime/compiler/library versions;
- a checksum manifest that makes missing arrays a test failure.

Expected arrays must be generated by executing the pinned reference, not by the Python port. If
the source cannot run, the cluster is blocked until a second independent implementation or a full
closed-form oracle is selected and that limitation is recorded.

### Clean-room licensing exception

When executable reference code has a license that cannot be incorporated into PhenoTypic, the
reference corpus and line-by-line reconciliation are owned by a separate oracle agent. The
production implementer must not receive or inspect that source. The oracle agent publishes only
provenance, source-produced fixtures, a source-free behavioral contract, and drift decisions. The
implementation agent works from the primary paper, compatible non-code sources, and that reviewed
contract. Record both identities and the information barrier in `PROVENANCE.json`. If role
separation cannot be demonstrated, stop and request a licensing decision rather than claiming a
clean-room port. A08 RORPO requires this exception.

## 3. Standalone logic scripts

One runnable script per algorithm lives at:

```text
docs/superpowers/logic_validation_scripts/
  2026-07-13-fungi-detection-method-ports/<method>.py
```

Scripts may import only the standard library, NumPy, and SciPy. They must not import `phenotypic`,
production modules, fixture-generation helpers, scikit-image, numba, GUDHI, FilFinder, or FilterPy.
Each script:

1. re-derives the load-bearing claim with a structurally different slow oracle;
2. checks exact algebraic cases before approximate image cases;
3. checks invalid/degenerate inputs where the claim has a boundary;
4. loads and verifies all expected fixture keys when a fixture is part of the claim;
5. prints assumptions, source revision, tolerance mechanism, and maximum observed error;
6. exits nonzero on any failure or silent skip.

FilFinder is the one external-wrapper exception. Its script validates only PhenoTypic-owned
numeric translations such as thresholding, label conversion, and unit-free pixel mapping. The
external library's own skeleton algorithm is covered by a source-version-pinned integration
fixture and smoke test, not falsely “re-derived.”

## 4. Tolerance derivation

No bare `rtol=1e-5` or “close enough” tolerance is accepted.

- Straight sums use Higham's accumulation bound
  \(\gamma_n = nu/(1-nu)\) multiplied by the sum of absolute terms.
- Heap/path recurrences add the per-edge rounding bound along the longest asserted path.
- Tensor eigenvalues convert component error to saliency error with Weyl's bound; near an
  isotropic tensor uses absolute tolerance because relative stick error is ill-conditioned.
- Convolution controls bound coefficient rounding plus accumulation length and compare away from
  boundaries separately from padding-sensitive pixels.
- Exact integer, graph-state, label, mask, and topology-count claims use equality.
- Monte Carlo is secondary only. A fixed seed, sample count, and explicit concentration interval
  are mandatory; simulation never replaces the exact binomial or combinatorial oracle.

Float32 production output may be compared with a float64 oracle only after the casting and
operation-count bound is written into the test. Any observed error larger than the derived bound
blocks the cluster rather than causing the bound to be widened without a mechanism.

## 5. Behavioral controls

Every numerical port includes controls from these categories when applicable:

- identity/zero/constant input;
- positive scaling and offset behavior;
- polarity inversion;
- transpose, reflection, and exact 90-degree rotation covariance;
- boundary and one-pixel threshold cases;
- multi-scale monotonicity when the output is a maximum across scales;
- deterministic tie-breaking;
- no input mutation;
- finite output, documented dtype, and shape preservation;
- exact legacy behavior when a new detector feature is disabled;
- full-image versus tiled behavior for transforms with nonlocal support.

These controls establish “this kind of algorithm behaves correctly.” They do not replace the
golden fixture that establishes “this is the selected algorithm.”

## 6. Mutation evidence

Each algorithm file lists its minimum mutant set. Mutation execution records one row per exact
single change:

| Method | Mutant ID | One changed expression | Command | Killing test | Max delta | Result |
|---|---|---|---|---|---:|---|

Rules:

- Apply one mutant at a time and show the diff contains only that mutation.
- A passing mutant is a test hole unless algebraically equivalent.
- Equivalent mutants require a proof and reviewer approval.
- Reintroduce the headline historical/likely bug and capture before/after output proving the
  golden test fails.
- A silent skip is a failure.

## 7. Common wrapper tests

Every operation wrapper must test:

- no required constructor arguments and keyword-only pydantic construction;
- field validation and list-to-tuple coercion where applicable;
- spy-based forwarding of every non-default helper argument;
- JSON and pipeline round-trip;
- only the permitted image layer changes;
- output contract and diagnostic-output warning;
- public `__all__` export, GUI discovery, taxonomy roster, typing alias, and tune annotations;
- a runnable Google-style docstring example using `load_synth_yeast_plate()`;
- missing optional dependency behavior at call time.

## 8. Common commands

```bash
uv run python docs/superpowers/logic_validation_scripts/2026-07-13-fungi-detection-method-ports/<method>.py
uv run pytest tests/unit/sdk_/reconnect/test_<method>.py -q
uv run pytest tests/unit/abc_/test_enhancer_taxonomy.py -q
uv run pytest tests/unit/tune/test_annotation_coverage.py -q
uv run pytest tests/unit/tune/test_enhance_annotations.py tests/unit/tune/test_detect_annotations.py -q
uv run mypy src/phenotypic
uv run ruff check
```

The cluster plan adds method-specific wrapper, detector, optional-dependency, and serialization
commands. The independent reviewer reruns commands in a clean worktree after clearing only the
affected Numba cache directory when applicable.
