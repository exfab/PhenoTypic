README.md

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Run every MeasureDinoEmbedding of a staged run on GPUs, in a Stage 4 after the store is final. One resident model per GPU shard, batched across images, with vectors that, within one GPU model and physical batch size, do not depend on sharding or batching (spec goal 3 as restated, S1).

Architecture:

  • P1 splits the embedder into a CPU prepare_regions, a backbone-only encode, and payload_from, so the inline path and Stage 4 share one crop geometry.
  • P2 adds the large models, compute_dtype, the determinism settings and the BatchEncoder, and measures batch invariance on three GPU models.
  • P3 adds the store transaction (replace_run_embeddings) and the Stage-4 signal. P4 wires a local Stage 4 with its refusals, deferral and resume.
  • P5 puts Stage 4 behind the recoverable SLURM controller (config v2). P6 runs --mode measure through it in republish mode. P7 is docs and the full regression.

Tech Stack: Python 3.12, pydantic v2, numpy, pyarrow, zarr v3 (OME-Zarr 0.5), click, torch 2.11 + transformers 5.x (the foundation extra), pytest, Slurm. Renderer: ~/.claude/tools/render_md_artifact.py.

This plan builds on it and leaves those two fields where they are; compute_block is their one producer and copies them into compute (O4, accepted with that condition).

  • #281 API this plan starts from, used unchanged:

    • regions objects | grid | objects-<name> | grid-<name>;

    • split_embedding_key (sdk_/_table_runs.py:205) is the one key parser;
    • MeasureEmbedding._layer_pixels (abc_/_measure_embedding.py:279) is the one pixel source.

  • --embed-stage {auto,gpu,inline}, default auto. Resolution table, spec §4.1:

    Mode auto resolves to

  • The resolved value is recorded as processing_state.json config "embed_stage" and job_metadata.json JobMetadataKey.EMBED_STAGE ("embed_stage"). It is never in the work-id digest (processing_configuration_digest_from_values, _cli_failure_tracker.py:276). A state without the key reads as "inline".

  • Refusals R1–R3 are each one click.UsageError line (exit 2). They sit in the read-only half, outside --skip-validation, above --restart, --overwrite, mint_run_identity and --dry-run. Pinned by tests/unit/cli/test_cli_preflight_ordering.py.

  • compute_dtype: Literal["float32", "bfloat16", "float16"] = "float32" on MeasureDinoEmbedding. It is part of the descriptor (top-level compute_dtype, absent reads "float32"). Storage stays float16 (EmbeddingDType, sdk_/typing_.py).

  • The per-entry compute block is {device, device_name, capability, torch, cuda, physical_batch, stage}, plus physical_batches when the entry's rows ran at more than one pass size. It is excluded from descriptor grouping. compute_dtype is not. compute_block(physical_batch=) takes one size or every size an image ran at (BatchEncoder.drain()'s DrainedTicket.physical_batches): one size is physical_batch; several are physical_batch: null plus physical_batches, largest first; none (no regions) is physical_batch: null (P1/P2 review I1).

  • Determinism, set once per Stage-4 process before the first load:

    • torch.backends.cudnn.deterministic = True, torch.backends.cudnn.benchmark = False;
    • torch.backends.cuda.matmul.allow_tf32 = False, torch.backends.cudnn.allow_tf32 = False;
    • torch.set_float32_matmul_precision("highest");
    • torch.use_deterministic_algorithms(True, warn_only=True);
    • CUBLAS_WORKSPACE_CONFIG: exported as :4096:8 by the Stage-4 SLURM script prelude, and setdefault to :4096:8 by the CLI right after --embed-stage resolves to gpu, before any strategy can create a cuBLAS handle (local Stage 4 runs in the CLI process; plan review I4). configure_determinism accepts :4096:8 or :16:8, the two deterministic values, so a user's own :16:8 is kept.

  • Physical batch: m = min(batch_size, pow2floor((0.8·GPU_mem − weights − 1 GiB) / per_sample)). It depends on the GPU model (total memory), the backbone and the input geometry only, never on free memory. Its one producer is physical_batch_for(model, *, crop_px, batch_size, compute_dtype, gpu_total_bytes) (_batch_encoder.py), which reads the weight bytes, tokens and heads from the loaded model; the P2 T4 job calls it too (P1/P2 review I3). m is per queue geometry: BatchEncoder(physical_batch=) takes an int or a rule (h, w) -> m, called once per queue, and Stage 4 passes physical_batch_for(model, crop_px=(h, w), ...) with the smallest batch_size of the backbone's embedders at that geometry (review I2). On OOM, that queue's m halves once for the shard, and each image records every pass size its rows ran at (compute.physical_batch / compute.physical_batches). At m = 1, or on a second OOM in that queue, the encoder raises Stage4OutOfMemory, refuses further use, and the shard exits non-zero. Constants live in P0's logic-validation script. Because m differs by GPU model and halving changes it, batch invariance is promised within one GPU model and physical batch (S1); across them the distance is measured (P2 T4).

  • A failed forward pass poisons the encoder. Any error in a pass (a bottomed-out OOM, a driver fault, a CUDA error that is not an OOM) re-queues the pass's rows, so no ticket or held_bytes changes, and every later submit, flush and drain raises RuntimeError chained from it (P1/P2 review I6). The shard fails; it never continues with that encoder.

  • Inside Stage 4, an embedder's device is cuda. A missing or unusable CUDA fails the shard, never falls back to CPU. The test-only escape is PHENOTYPIC_STAGE4_DEVICE=cpu.

  • Nothing is rewritten after the record that certifies it. Stage 3 (and the single-pass core in a Stage-4 run) writes the store with its measurements and stages.stage3, and writes no record and no embeddings. Stage 4 writes the embeddings (one store transaction), then the record, then consumes its signals, in that order.

  • One "done" predicate. Under deferral, stages_1_to_3_done (a Stage-3 marker, a store that matches the work id, a measurement table) means Stages 1–3 are finished: every recovery shortcut returns early on it and publishes nothing, and every core that re-runs an image deletes that image's Stage-4 signals first (P4 T2).

  • Signals: .phenotypic/progress/stage4_payload/<ds>/<model>/<layer>/<region>/<stem>.parquet, atomic, with work_id, run_id and root_sha256 in the Parquet key-value metadata. A signal is valid only at the live root; a stale one is deleted and its key re-embedded. Signals are reused per key, and a round that wrote signals has made progress (P3 T2, P4 T3, P5 T1).

  • A stalled Stage 4 ends unfinished (U7): after two unchanged rounds the finalizer runs, the leftover images keep no record and no journal row, and the run exits 5. GPU OOM and a changed root are never terminal per-image failures.

  • Measure mode (U8, U10): the measure core carries the image's existing embeddings forward; a Stage-4 failure keeps them and a valid record, and is journalled as MEASURE_FAILURE_STAGE (exit 3). SLURM measure runs on the staged controller with a measure-mode finalizer that writes no forward run proof. Republish has one carrier, the manifest flag (manifest v5).

  • U5: an unpinned revision is resolved once, at a run's first submission, for Stage-4 runs only (O9); a continuation reuses the recorded commit.

  • Commit pool and loader: one commit thread; one DataLoader per backbone, spawn context, not persistent, identity collate_fn, processors loaded in the main process and pickled into the dataset. Workers: resolve_local_worker_count(config.n_jobs, n) − 1 locally (--njobs 1 runs it in-process) and resolve_local_worker_count(-1, n) − 1 on a SLURM shard (the allocation), _cli_utils.py:88.

  • The encoder's in-flight bound is in bytes (MAX_IN_FLIGHT_OUTPUT_BYTES), so crop pipelines keep full batches and only masked_dense feature grids flush early.

  • No CUDA for a local --embed-stage gpu is exit 1, one line, before Stage 1: an environment error, not a usage error.

  • The revision an entry records comes only from resolved_revision(model); no #282 code reads config._commit_hash (transformers ≥ 5.18 stopped setting it; the #281 fallback lives in resolved_revision).

  • Process mode (copy and in place) and AutoConvertRaw-GC's direct process_single_apply_only_core calls stay inline on CPU, byte for byte (H5).

  • No new resource flags: Stage 4 runs on resolve_stage_slurm_args(gpu_slurm_args, slurm_args) (_cli_staged_slurm.py:110) and --gpu-shards (H6).

  • Heavy imports (torch, transformers, huggingface_hub) stay inside functions. tests/unit/ci/test_startup_imports.py and test_deferred_imports.py stay green. sdk_ never imports _cli (tests/unit/sdk_/test_run_state_layering.py).

  • No file under src/phenotypic/_gui/ changes. The run-console control for --embed-stage is a GUI follow-up (spec §6); see "Follow-ups".

  • MeasurementInfo members get label/desc only, never bio_desc.

    • class BatchEncoder:
      • __init__(self, model: Any, processor: Any, *, device: str, compute_dtype: ComputeDType, physical_batch: int, max_in_flight_bytes: int = MAX_IN_FLIGHT_OUTPUT_BYTES)
      • submit(self, ticket: Hashable, inputs: BackboneInputs) -> None. Queues inputs' rows by (h, w, pooling), one queue per key. A full queue runs at once. A zero-row submission completes at once, with no forward pass. When the output bytes held for unfinished tickets exceed max_in_flight_bytes, every partial queue is flushed (zero-padded). The bound is in bytes, not images (re-review item 4): a crop ticket holds N · D · 4 bytes, so crop pipelines never reach it and keep full batches; a masked_dense ticket holds its feature grid (ENCODER_OUTPUT_BYTES), so only those flush early (plan review I2).
      • held_bytes: int (read-only): the output bytes held for unfinished tickets.
      • flush(self) -> None: runs every partial queue, zero-padded to exactly physical_batch.
      • drain(self) -> Iterator[tuple[Hashable, list[np.ndarray]]]: yields each ticket as soon as all its rows are done, in completion order, not submission order, and drops its buffers when yielded. Outputs are shaped as RegionEncoder.run (P1 T1) returns them.
      • physical_batch: int (read-only), halve(self) -> bool: halves it once; False when already halved or at 1.
      • as_region_encoder(self) -> RegionEncoder: a synchronous adaptor (submit, flush, drain one ticket), so MeasureEmbedding.encode runs on it in tests.
    • Every forward pass has exactly physical_batch inputs. Crops are normalised as embed_crops normalises them (_dino_support.py:449-462); tiles arrive already normalised by the processor (P1 T2). Both are cast to compute_dtype and run under torch.inference_mode(); CLS, mean and patch outputs are taken in float32.
    • class Stage4OutOfMemory(RuntimeError): raised by a forward pass that runs out of memory when halve() returns False. A batch that ran out of memory is retried whole at the halved size, so no row is lost.

Goal: A SLURM run with Stage 4 on goes through the recoverable controller. After the last Stage-3 chunk the controller classifies Stage 4 and submits GPU rounds over a per-round worklist, until nothing is retryable or two rounds make no progress; then it submits the finalizer. A stall ends unfinished (U7): the leftover images keep no record and no journal row, and the run exits 5. A run with no GpuDetector and --gpu-slurm gets the same controller with phases ["stage3", "stage4"].
