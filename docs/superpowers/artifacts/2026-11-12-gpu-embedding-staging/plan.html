README.md

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: Run every MeasureDinoEmbedding of a staged run on GPUs, in a Stage 4 after the store is final. One resident model per GPU shard, batched across images, with vectors that do not depend on sharding or batching.

Architecture:

  • P1 splits the embedder into a CPU prepare_regions, a backbone-only encode, and payload_from, so the inline path and Stage 4 share one crop geometry.
  • P2 adds the large models, compute_dtype, the determinism settings and the BatchEncoder, and measures batch invariance on three GPU models.
  • P3 adds the store transaction (replace_run_embeddings) and the Stage-4 signal. P4 wires a local Stage 4 with its refusals, deferral and resume.
  • P5 puts Stage 4 behind the recoverable SLURM controller (config v2). P6 runs --mode measure through it in republish mode. P7 is docs and the full regression.

Tech Stack: Python 3.12, pydantic v2, numpy, pyarrow, zarr v3 (OME-Zarr 0.5), click, torch 2.11 + transformers 5.x (the foundation extra), pytest, Slurm. Renderer: ~/.claude/tools/render_md_artifact.py.

Global Constraints

  • #281's device-provenance change has landed (b6714d28d, d3c54f723): model.device and model.device_name are recorded per entry and ignored by descriptor grouping (_cli_embedding_deliverables.py:108, _PROVENANCE_MODEL_FIELDS). This plan builds on it and leaves those two fields where they are (open question O4).

  • #281 API this plan starts from, used unchanged:

    • keys <model>/<layer>/<region>;
    • regions objects | grid | objects-<name> | grid-<name>;
    • MeasureEmbedding.name and .layer;
    • split_embedding_key (sdk_/_table_runs.py:205) is the one key parser;
    • MeasureEmbedding._layer_pixels (abc_/_measure_embedding.py:279) is the one pixel source.

  • --embed-stage {auto,gpu,inline}, default auto. Resolution table, spec §4.1:

    Mode auto resolves to
    full, SLURM, GpuDetector or --gpu-slurm given gpu
    full, SLURM, neither inline
    full, local inline
    --mode measure, SLURM with --gpu-slurm gpu
    --mode measure, otherwise inline
    --mode process (copy or in place) inline; an explicit gpu is refused (R1)
    a pipeline with no in-scope embedder inline (open question O5)

  • The resolved value is recorded as processing_state.json config "embed_stage" and job_metadata.json JobMetadataKey.EMBED_STAGE ("embed_stage"). It is never in the work-id digest (processing_configuration_digest_from_values, _cli_failure_tracker.py:276). A state without the key reads as "inline".

  • Refusals R1–R3 are each one click.UsageError line (exit 2). They sit in the read-only half, outside --skip-validation, above --restart, --overwrite, mint_run_identity and --dry-run. Pinned by tests/unit/cli/test_cli_preflight_ordering.py.

  • compute_dtype: Literal["float32", "bfloat16", "float16"] = "float32" on MeasureDinoEmbedding. It is part of the descriptor (top-level compute_dtype, absent reads "float32"). Storage stays float16 (EmbeddingDType, sdk_/typing_.py).

  • The per-entry compute block is {device, device_name, capability, torch, cuda, physical_batch, stage}. It is excluded from descriptor grouping. compute_dtype is not.

  • Determinism, set once per Stage-4 process before the first load:

    • torch.backends.cudnn.deterministic = True, torch.backends.cudnn.benchmark = False;
    • torch.backends.cuda.matmul.allow_tf32 = False, torch.backends.cudnn.allow_tf32 = False;
    • torch.set_float32_matmul_precision("highest");
    • torch.use_deterministic_algorithms(True, warn_only=True);
    • the Stage-4 script prelude exports CUBLAS_WORKSPACE_CONFIG=:4096:8.

  • Physical batch: m = min(batch_size, pow2floor((0.8·GPU_mem − weights − 1 GiB) / per_sample)). It depends on the GPU model (total memory), the backbone and crop_px only, never on free memory. On OOM, m halves once for the shard and is recorded in compute.physical_batch. At m = 1, or on a second OOM, the shard exits non-zero. Constants live in P0's logic-validation script.

  • Inside Stage 4, an embedder's device is cuda. A missing or unusable CUDA fails the shard, never falls back to CPU. The test-only escape is PHENOTYPIC_STAGE4_DEVICE=cpu.

  • One writer per artifact. Stage 3 (and the single-pass core in a Stage-4 run) writes the store with its measurements and stages.stage3, and writes no record and no embeddings. Stage 4 writes the embeddings (one store transaction), then the record, then consumes its signals, in that order.

  • Signals: .phenotypic/progress/stage4_payload/<ds>/<model>/<layer>/<region>/<stem>.parquet, atomic, with work_id, run_id and root_sha256 in the Parquet key-value metadata.

  • Process mode (copy and in place) and AutoConvertRaw-GC's direct process_single_apply_only_core calls stay inline on CPU, byte for byte (H5).

  • No new resource flags: Stage 4 runs on resolve_stage_slurm_args(gpu_slurm_args, slurm_args) (_cli_staged_slurm.py:110) and --gpu-shards (H6).

  • Heavy imports (torch, transformers, huggingface_hub) stay inside functions. tests/unit/ci/test_startup_imports.py and test_deferred_imports.py stay green. sdk_ never imports _cli (tests/unit/sdk_/test_run_state_layering.py).

  • No file under src/phenotypic/_gui/ changes. The run-console control for --embed-stage is a GUI follow-up (spec §6).

  • MeasurementInfo members get label/desc only, never bio_desc.

Review Focus

Inputs the spec implies but names no test for. Each is pinned in the task named.

  1. An image with no colonies, or an image whose every embedder is objects-only on an empty objmap. Inline gives an empty table (_embed_vectors, abc_/_measure_embedding.py:485). Stage 4 must submit nothing to the GPU for it, still commit an empty table, and publish its record; it must not stall a batch waiting for rows. Pinned in P2 T3 (test_an_empty_input_completes_without_a_forward_pass) and P4 T3 (test_an_image_with_no_colonies_commits_an_empty_table).
  2. A per-image error raised inside a DataLoader worker process (GridCellOutsideImageError on one plate, a corrupt store). It must cross the process boundary as that image's stage4 failure; the loader, the shard and the other images go on. Pinned in P4 T3 (test_a_loader_worker_error_fails_only_its_image).
  3. --embed-stage gpu on a machine with no CUDA, locally. The run must stop with one error line and exit 1, journal no per-image failure, and leave every image Stage-4 pending, so a re-run on a GPU node finishes it. Pinned in P4 T3 (test_no_cuda_fails_the_stage_without_journalling_images).
  4. More GPU shards than retryable images (--gpu-shards 4, one image left after a walltime). Empty shards exit 0, are not progress and not failure, and the next classification sees the one image. Pinned in P5 T1 (test_more_shards_than_work_leaves_empty_shards_harmless).
  5. The same command run again after the run finished. No image re-embeds, no GPU array is submitted (the controller goes straight to the finalizer), and every store root is byte-unchanged. Pinned in P4 T4 (test_a_finished_run_rerun_embeds_nothing) and P5 T1 (test_all_done_goes_straight_to_the_finalizer).

Decisions this plan takes where the spec leaves the builder a choice (§7):

  • device_map={"":"cuda"} needs accelerate. The plan loads with from_pretrained(dtype=compute_dtype) then .to("cuda") instead, so the foundation extra gains no dependency. 7B in bf16 is 13.4 GB of host RAM during the load, inside a 48 GB --mem. P2 T1 Step 5 records the peak.
  • The commit pool has 2 threads; the DataLoader has cpus_per_task − 1 workers (local: len(os.sched_getaffinity(0)) − 1), prefetch_factor=2.
  • A signal carries root_sha256, the root its payloads were computed against, so a commit in a later round uses the right expected_root_sha256.
  • Stage 4 reads an unpinned revision from BackboneKey.revision and never rewrites the embedder's revision field, so producer.params_sha256 is the same as an inline run's.

Open questions

Each blocks only the task named; the plan is written with the recommended default and marks it (pending Ox).

  • O1 (P2 T1). Where the new sizes live. DinoSize (sdk_/typing_.py:163) is shared by DinoSam2Detector, FssDinoDetector and Insid3Detector. Extending it, as spec §4.5 says literally, lets those detectors accept and tune-enumerate giant/huge_plus/7b. Recommended: a separate EmbeddingDinoSize Literal for the embedder only.
  • O2 (P2 T1). Model tokens for the new sizes. They become folder names and keys. Recommended: the hub's own spelling, dinov2-vitg14, dinov3-vith16plus, dinov3-vit7b16.
  • O3 (P4 T1). A non-DINO MeasureEmbedding in a Stage-4 run. Stage 4 has backbone code only for DINO. Recommended: refuse it under R2's line, since running it inline would mix CPU into a GPU run.
  • O4 (P2 T1). compute beside #281's model.device/model.device_name. Recommended: keep both; compute.device and compute.device_name repeat them, so #281 entries keep their shape.
  • O5 (P4 T1). --embed-stage gpu with no in-scope embedder. Recommended: resolve inline and print one note line; not a refusal.
  • O6 (P5 T3). What "too few images per shard to pay off the cold load" means. Recommended: warn when the cold load exceeds the shard's estimated warm GPU time (about 200 images per shard for DINOv2-base at the measured 3.8 s/image and 750 s cold). The alternative, break-even against inline CPU, is about 12.
  • O7 (P6 T2). SLURM measure mode moves engines. With Stage 4 on, a SLURM --mode measure runs through the staged controller (phases ["stage3","stage4"], a measure role) instead of AutonomousSLURMStrategy. The spec implies this (U4 and §4.6 need controller rounds) but does not say it.
  • O8 (P5 T1). The spec's "exit 3" on zero progress. phenotypic-wait exits 3 only when every accepted image is verified or failed. The loop (spec §4.4; every step is an active_check() point):

  1. Licence: for every v3 BackboneKey, require_license_acceptance(..., interactive=False) before any load. Then stage4_device() and configure_determinism().
  2. Per item, in order: the run id is owned_table_run_id(block, run_pipeline_sha256); then
    • record already valid with signals left over → delete_stage4_signals (orphan);
    • store holds every key fresh, producer.params_sha256 and compute_dtype matching → publish only;
    • stage4_signals_complete → commit only;
    • otherwise → to the loader.
  3. Per backbone, in plan order: load once through the measurer module's load_dino_backbone (so the test stub applies; never _cached_backbone), with dtype=key.compute_dtype; compute m; stream the loader's images through one BatchEncoder; as each (image, key) completes, vectors_from → payload_from(prepared, vectors, entry_descriptor_for(model, compute_block(..., stage="stage4", physical_batch=m))) → write_stage4_signal(..., root_sha256=<the root the loader read>). Then del the model and torch.cuda.empty_cache().
  4. A ThreadPoolExecutor(max_workers=2) commits each image whose signals are complete, under commit_guard: replace_run_embeddings(store, run_id, payloads, expected_root_sha256=signal.root_sha256, objmap_sha256=..., array_sha256=...) with the digests taken from the payloads' binds (equal to the store's, because the root matched); then the record (publish_image_success, mode="full", the artifacts Stage 3 used to publish, _cli_staged_slurm_worker.py:572-603); then delete_stage4_signals. republish=True is P6 T1.
  5. A per-image exception returns a picklable FailedImage(identity, error_type, message, traceback); it never raises through the loader.
