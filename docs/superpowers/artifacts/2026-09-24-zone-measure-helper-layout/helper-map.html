Short answer

In production code, every helper function in _measure_orientation_zones.py is used only by MeasureOrientationZones itself (directly, or through another helper it calls). No other module under src/ imports any of them. One function, radial_relative_field, has no production caller at all; only tests call it.

The public-looking names exist because two other groups import them: the unit tests (12 names) and 15 research scripts under docs/superpowers/specs/2026-07-15-orientation-field/scripts/ (12 names). The sharing between the two operations does not happen through imports. It happens through copies: the circle helper, the Okabe-Ito colors, the distance map, and the axial-difference formula each exist in two to four places.

Proposals for reformatting

Placement rule

  1. Shared goes to sdk_. A helper used by two or more production modules, or a numeric primitive that has its own unit tests, lives in sdk_ and is exported from its subpackage __init__.
  2. Operation-only goes on the class. A helper that exists to build one operation's columns or figures becomes a private method (@staticmethod if it reads no state) and is called as self._name(...), never as ClassName._name(...).
  3. No public-looking names at module level in an operation file. Module scope keeps only private constants and private value types.
  4. Dead code is deleted, not kept for compatibility.

Numeric orientation-field primitives move to sdk_/orientation_fields, which already describes itself as "transforms on already-computed orientation fields". Everything that encodes this operation's vocabulary (Radial/Mask variants, zone names, column writers, figure traces) becomes private on the class. The 1,733 lines of figure code move to a private mixin so the class file reads as a measurement.

Why not everything on the class: the ring-profile functions are tested one by one, are imported by 15 research scripts, and one of them already has a second copy in the resolver. They are shared in practice even though only one class calls them today.

Trade-off: the orientation op becomes a small package, so the class and its figure mixin sit in two files. Every figure method is still reached through self._add_*, so a search for its name still finds every caller.

Suggested order of work

The orientation golden test (test_orientation_zone_migration_golden.py) compares at rtol = atol = 1e-10. That tolerance is the check that separates a move from a behavior change, so the order below keeps the two apart.

  1. Delete dead code. The seven SymZones definitions, radial_relative_field, and the stale L110 comment. No numeric effect.

  2. Move without changing arithmetic. Relocate functions to their new homes and convert call sites to self._x. The golden must pass unchanged. Update tests/unit/ci/test_deferred_imports.py for any moved function that imports lazily, and keep the palette and geometry modules free of plotly: sdk_/viz/__init__.py imports .figures, which imports plotly at module scope, so a module under sdk_/viz/ would break the startup import gate.

  3. Consolidate the copies, one commit each. The single axial-difference function, the single distance map, and the resolver calling the shared radial-tilt helper. Each of these can change results in the last bits or at exact 90° ties, so each is a behavior decision with its golden re-checked.

  4. Update or retire the research scripts. Either repoint the 15 scripts' imports, or record in the spec folder that they run against commit 249d2d6 or earlier.

Questions, answered

  1. 90° fix elsewhere: not needed. The other copies already drop or neutralise an exact 90° change (see the corrected card above), so nothing changed their behaviour.
  2. Thresholds: the ring-level ones (minimum crossings and ring resultant) now follow zone_min_crossings and zone_min_resultant in both canonical and legacy mode. The per-pixel coherence, per-crossing resultant and crossing half-width floors are a different level of evidence, so they stay fixed, now as one set of shared constants.
  3. Research scripts: documented, not updated. The spec README lists the 17 affected scripts and a table mapping each old import to its new location.

Line numbers and counts in the tables above describe the tree as traced at fb3751f2, before the refactor.
