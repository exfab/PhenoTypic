README.md

For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

Goal: The GUI reads #281's contract (exit codes 3/4, per-pipeline table folders, TSV, .pht-*.json), measurements.csv is retired, a run that finished with failed images is shown, curated and relaunched as such, and the run console reaches #282's Stage 4 and --mode measure.

Architecture:

  • One verdict. run_finished_with_failures(state, output_dir) in sdk_/_run_state.py is the failed-run twin of rule 1. The waiter, the registry, the observer, the badge, the claim gate and the mutation guard all ask it, each with the RunState it already resolved (PA1).
  • Exit codes by name. submit_slurm and observe_local_exit classify by RunExitCode. A new terminal status complete_with_failures carries failed_images (PA1).
  • TSV everywhere a writer exists; the CSV mirror is retired by finalize and by curation after the TSV lands, never before (PA3).
  • PR B factors resolve_embed_stage_for_pipeline out of _cli_embed_stage.py, so the form's visibility, hint and refusals are the CLI's own functions (PB1–PB2), and adds a cli_mode selector for --mode measure (PB3).

Tech Stack: Python 3.12, Dash/Flask, polars, pyarrow, zarr v3, click, pytest (+ Playwright under PLAYWRIGHT=1), Slurm. Renderer: ~/.claude/tools/render_md_artifact.py.

Global Constraints

  • Exit codes are phenotypic.sdk_.RunExitCode (sdk_/_exit_codes.py:42-47): 0 COMPLETE, 1 ERROR, 3 COMPLETE_WITH_FAILURES, 4 SUBMITTED, 5 ENDED_UNPUBLISHED, 6 WAIT_TIMEOUT; 2 is Click's usage error. No GUI code compares against a literal.
  • Readers rule (_gui/CLAUDE.md, "Importing readers"): a GUI module asking "did this run finish (with failures)?" imports from phenotypic.sdk_ only. The single exception is the SLURM observer's finished_run_outcome (_cli/_cli_wait.py). Every new reader gets a row in docs/source/contrib_guide/tracked_state.md's Known consumers table (:433-450) in the same commit (:18, 525).
  • sdk_ never imports _cli (tests/unit/sdk_/test_run_state_layering.py).
  • The verdict never asks valid_aggregate_snapshot; it uses _valid_aggregate_proof (GUI-tolerant, sdk_/_run_state.py:1397-1433).
  • Status vocabulary: the new literal is exactly complete_with_failures; label complete · N failed (Recent Runs, banner), badge Run complete · N images failed (warning), colour --oi-orange-text. incomplete is never persisted (D13).
  • The claim gate allows only complete and a confirmed complete_with_failures; it refuses the five states in spec PA11's table, and a process tree with failures (N4).
  • CSV retirement: measurements.csv is unlinked only after its TSV is published, and in finalize inside commit_guard when one is given. _KEPT_CSV_STEMS == {"error_analysis", "metadata"}: error_analysis.csv stays CSV (D18) and metadata.<ext> is never swept. MEASUREMENTS_CSV, measurements_csv_path, BundleLayout.mirror_csv stay defined as legacy read names. _GUI_WRITTEN_PROOF_DESCRIPTORS keeps measurements_csv.
  • The verdict is run_finished_with_failures(state, output_dir); its config comes from RunState.finalization_digests and .process_only_layer, filled by resolve_run_state's one read (spec PA4). An all-failed run is confirmed through the no-proof arm (D16), which tests the marker by path and refuses a master or mirror Parquet left by another generation. It reads no fence (R3-I1). The claim gate gives that stale-deliverables case its own remedy (--retry-failures from the CLI until an image verifies, or --overwrite).
  • --accept-failures maps only 3 to 0 (D15). The exit-5 variant prints only when this generation published an aggregate proof, and names a store only through excluded_store_names (the per-image unprojectable predicate, shared with _advisories), never from "verified minus sources".   • D17: the claim gate cannot see a local CLI run; the docs say so, and no task adds a lock.
  • Suffixes: canonical .pht-pipe.json, .pht-op.json, .pht-cc.json, .pht-tune.json; legacy .json.pht-* read-only; a plain pipeline.json is never removed (#281 A4).

  • TSV inputs: sdk_.INPUT_TABLE_SUFFIXES ({".csv", ".tsv"}), delimiter by sdk_.delimiter_for, reading by sdk_.read_delimited, writing by sdk_.write_tsv.
  • No CLI exit-code value changes. D14 tightens rule 3 only; its exit-5 line gains the variant text fixed in spec PA4 (N3).
  • No edit outside the repository (D12): the ucr_029/ucr_033 scripts are the user's.

Conventions for every task

  • Shared-env test command (run-phenotypic-test skill: headless Qt, never -n auto, no streamed output, no -x), from the worktree root:

    PT='env QT_QPA_PLATFORM=offscreen uv run pytest -q --no-header -p no:randomly -o addopts= -m "not slow"'

    The env is synced with uv sync --group dev --group test-qt --group docs --extra gui --extra napari --extra tune --extra topology (root CLAUDE.md); without tune/topology a gate shows 24 false failures.

  • Lanes: tests/unit, tests/integration, tests/gui (all in testpaths); Playwright PLAYWRIGHT=1 $PT tests/e2e/gui -m "not slow and not ci_flaky"; live CPU SLURM PHENOTYPIC_RUN_LIVE_SLURM=1 (tests/integration/gui/test_run_console_slurm_live.py); live GPU (PB4, new flag PHENOTYPIC_RUN_LIVE_SLURM_GPU=1).

  • Lint: uv run ruff check --fix <the paths you changed>, never bare. uv run mypy src/phenotypic at each phase gate; no new errors over the branch's baseline.

  • Commits: explicit paths, never git add -A; end with the session's attribution lines.

  • Fixtures are built with the real publishers, never hand-written JSON (the tests/_output_layout.py rule, :448-470). New shared helpers live in tests/_output_layout.py; the first task that needs one creates it under Create (helpers), later tasks reuse it.

  • Mutation checks (the porting-a-reference-algorithm discipline), by deletion of one conjunct at a time, never by inversion (plan review C2): the verdict (PA1 T1), waiter rule 3 (PA1 T2), the claim-gate condition and the N reset (PA1 T3), the cancel/bind paths (PA1 T4), the CSV-after-TSV order and the pre-PA8 descriptor (PA3 T1), and the guard's three run_permits_mutation calls (PA5 T1). The task names each mutant and the test that must fail. Back up by full path, mutate, run, restore from the saved bytes and hash-check; never git checkout -- (it once wiped a subagent's uncommitted fixes). A mutant that survives stops the cluster.

  • Independent-reader check where a deliverable's bytes change (PA3): read the TSV with pandas.read_csv(sep="\t", dtype=str, keep_default_na=False) and the Parquet with pyarrow.parquet.read_table, never with the writer's own reader. No task changes a store.

  • Gates (root CLAUDE.md, "Focused between phases"):

    • per task: the task's test files, seconds to a minute;
    • per phase: the affected surface once, from importers of the changed modules (grep -rl <module> tests/), on Slurm when over a couple of minutes;
    • end of each PR: one full sharded regression, after the rebase for PR A.

  • Gate shape (precedent /bigdata/exfab/anguy344/gate-results/final/make_gate.sh): a detached worktree at the gated SHA under /bigdata/exfab/anguy344/gate-worktrees/<cluster>-<sha9>; on batch or intel (never preempt; short only for an array whose tasks fit 2 h), explicit --mem/--time, -n $SLURM_CPUS_PER_TASK; logs under /bigdata/exfab/anguy344/gate-results/guiplan/<cluster>/, never /scratch. The job script cds to the worktree path it was given, never cd "$SLURM_SUBMIT_DIR". Each shard prints dirty=0 at start and end. An afterany cleanup job removes the worktree.

  • Docs builds are Slurm jobs: sphinx-build -j "$SLURM_CPUS_PER_TASK" -D nbsphinx_execute=never; read the rendered HTML of each changed page afterwards.

  • GPU jobs (PB4 only): slurm-job skill; measure sbatch --test-only on exfab (--account=exfab) and short_gpu --constraint=gpu_latest and take the earlier start.
